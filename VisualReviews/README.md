## Publication convention

- Use `VisualReviews/<Area>/<Milestone>/` for a compact review package.
- Prefer 3–6 selected images: variant comparisons, representative in-engine views and before/after comparisons when useful.
- Include a concise report, relevant non-sensitive artistic parameters/seeds, test scope, known defects and approval status.
- Images must be actual development captures; label concept art or diagnostic plots separately. Compression/resize is acceptable, visual retouching must not misrepresent the result.
- Never upload game source code, Unreal projects/packages, original third-party assets, credentials, full logs, local machine paths or confidential internal documentation.
- Keep earlier published revisions accessible through Git history. Do not rewrite public history.
- After publishing, verify the commit and anonymously GET each important `raw.githubusercontent.com/<owner>/<repo>/<commit>/<path>` URL. Confirm HTTP success, image content type and hash against the reviewed local file.
- Share links pinned to the verified commit, together with the report and a brief evaluation brief. Do not claim publication while only local staging or unreferenced Git objects exist.
- Repository visibility must not change without explicit owner approval. Public images here are review artifacts; no original asset redistribution license is granted.
